ODD / EVEN LAB v1.3 — INDEXEDDB PERSISTENCE

Why this version exists
- v1.2 still relied on localStorage as the durable store.
- If the browser origin is near localStorage quota (for example because Under-9 and other research modules also persist data), refresh can still make the Odd/Even cohort appear to restart.

What changed
1. IndexedDB is now the primary durable store for the Odd/Even UI, frozen cohort registry and cumulative forward progress.
2. localStorage is retained only as a small mirror/fallback.
3. The app restores IndexedDB BEFORE connecting the public tick feed.
4. The panel now displays its persistence backend and verification time.
5. pagehide triggers a final save attempt.
6. The strict cohort, candidate hashes, forward counters, wake lock, SHADOW/DEMO/REAL logic and admin-only controls are retained.

Upload
- Replace odd-even-research-v1-private.js with the new file.
- The HTML does not require a change if it already loads /odd-even-research-v1-private.js.
- Redeploy and hard-refresh once.

Test
1. Start SHADOW and let Total Forward Ticks reach at least 20.
2. Note the Cohort ID.
3. Confirm the panel says Persistence: IndexedDB + localStorage mirror.
4. Refresh the page.
5. The same Cohort ID and cumulative forward count should return. A short feature warm-up after reload is normal.

If the panel says IndexedDB unavailable or IndexedDB write failed, export a screenshot/report of that exact message before refreshing again.
