DERIV PROPOSAL RATE-LIMIT FIX

Observed error:
  RateLimit: You have reached the rate limit for proposal.

Root cause:
The tick-driven engine can have a recovery proposal prefetch in flight when a
fast-loss tick arrives. The loss path previously did not wait for that prefetch;
it could immediately issue a second proposal for the same next trade. Repeated
through a recovery chain, that creates proposal bursts and Deriv rate-limits
the connection.

Fixes:
1. Exactly one tracked recovery-prefetch task per session.
2. Fast-loss processing first consumes the ready prefetched proposal.
3. If prefetch is still in flight, it waits up to 800 ms for that SAME request
   instead of immediately issuing a duplicate.
4. Proposal calls are serialized per Deriv WebSocket connection.
5. Proposal calls are spaced by at least 350 ms.
6. Explicit Deriv RateLimit responses back off and retry up to two times.
7. BUY calls are NOT retried or throttled by this mechanism, so duplicate
   contract purchases are not introduced.
8. Tick-driven win/loss behavior and background settlement remain unchanged.

Replace all four files:
  app/engine.py
  app/deriv_ws.py
  backend/app/engine.py
  backend/app/deriv_ws.py

Then fully restart the backend service.
