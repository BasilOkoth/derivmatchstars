DERIV PROPOSAL TIMEOUT FIX

Observed error:
  PROPOSAL [R_10/USD/digit 3]:
  Deriv WebSocket request timed out after 15s

Root cause in the modern /app client:
The same WebSocket reader that receives req_id responses also awaited
subscription settlement callbacks. A settlement callback can immediately
request the next proposal. It then waits for a proposal response that only
the blocked reader can consume, causing the exact 15 second timeout.

Fixes:
1. Subscription callbacks are now scheduled as independent asyncio tasks.
   The WebSocket reader never waits for strategy/settlement work.
2. Added a connection lock so concurrent callers cannot open competing socket
   connections/readers.
3. Proposal requests safely reconnect and retry ONCE after a timeout.
   Proposal is read-only and does not purchase a contract.
4. BUY requests are NOT automatically retried. Retrying BUY blindly could
   duplicate a purchase.
5. The legacy /backend/app WebSocket client also gets connection/send locking,
   timeout cleanup and one safe proposal retry.

Replace:
  app/deriv_ws.py
  backend/app/deriv_ws.py

engine.py copies are included for reference but are unchanged from the uploaded
repository. If you already applied the low-latency engine.py patch from the
previous package, KEEP those low-latency engine.py files; do not overwrite them
with the reference copies in this package.

After replacing deriv_ws.py, restart the backend service.
