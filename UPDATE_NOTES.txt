LOW-LATENCY EXECUTION FIX

Replace all four files:
  app/engine.py
  app/deriv_ws.py
  backend/app/engine.py
  backend/app/deriv_ws.py

Why the bot was still delayed:
1. The repository contains two backend engines. backend/app was an older engine
   that sleeps 500 ms and polls settlement serially.
2. Even the newer app engine waited for a Deriv `forget` response after a loss
   before starting the next recovery.
3. Recovery proposal prefetch started only after the contract-subscription
   request completed, wasting a WebSocket round trip.
4. When Deriv supplies no subscription id, fallback polling was every 150 ms.

Changes:
- Both /app and /backend/app now use the same event-driven engine.
- Recovery proposal prefetch starts immediately after BUY confirmation.
- Old subscription cleanup is fire-and-forget.
- On a confirmed loss, recovery execution continues immediately in the same
  settlement task after the session lock is released.
- No-subscription fallback poll interval reduced from 150 ms to 50 ms.
- Existing duplicate/open-contract protections remain intact.

Important:
A Deriv order cannot be guaranteed to BUY on the exact same public tick that
triggered it: proposal/buy are network requests and Deriv controls processing.
This patch removes avoidable application-side waits so a PREARMED recovery buy
is sent as soon as settlement is authoritative.

After replacing files, restart the Render service/backend process.
