RECONCILING deadlock fix

Replace BOTH:
- app/deriv_ws.py
- app/engine.py

Root cause:
The previous no-subscription fallback called the settlement callback with
`await callback(data)` from inside subscribe_contract(). The engine calls
subscribe_contract() while holding the per-session asyncio.Lock, and the
settlement callback tries to acquire that same lock. asyncio.Lock is not
re-entrant, so the session could stay forever on:

  RECONCILING
  Checking unresolved contract <id>

Fix:
- Initial proposal_open_contract responses without subscription.id are now
  delivered with asyncio.create_task(callback(data)), never awaited inline.
- subscribe_contract() returns immediately.
- engine.step() can release its session lock.
- The callback can then acquire the lock and settle the contract.
- If the first response is still open, engine.py's 150 ms polling fallback
  continues until Deriv reports is_sold.

After deployment:
Restart the backend process. Existing sessions with open_contract_id will be
picked up by the engine and reconciled automatically when they are running.
If a session was automatically stopped by an earlier ERROR, press START BOT
once so the worker re-enters reconciliation.

Both Python files were syntax-compiled successfully.
