DigitMatchStar Odd/Even Lab v1.2 — PERSISTENCE FIX

Problem fixed
- v1.1 could appear to reset to 0 after refresh when browser localStorage was near quota.
- Odd/Even v1.0 stored a large single blob (history + live ticks + records). Under-9 uses the same site origin, so combined browser storage could exceed localStorage quota.
- v1.1 swallowed localStorage write failures, so the cohort/counters could look saved during the session but disappear after refresh.

Changes
- Keeps the strict cohort design from v1.1.
- Removes only the obsolete Odd/Even v1.0 storage key on startup. It does NOT delete Under-9 storage.
- Cohort registry remains compact and persistent.
- Cumulative candidate forward counts, total forward ticks, execution stats, forward start epoch and last feature epoch are stored in a compact progress record.
- Large raw forward/live arrays are no longer written to localStorage.
- After refresh the same cohort ID and cumulative candidate counters should return.
- The feed performs warm-up again, then continues the same cohort without rediscovery.
- Persistence failures are now shown visibly in the panel instead of being silently ignored.
- REAL still never auto-resumes after reload.

Upload
1. Replace odd-even-research-v1-private.js with the included file.
2. The existing HTML can remain unchanged because it already loads /odd-even-research-v1-private.js.
3. Redeploy / hard-refresh.
4. Let a fresh strict cohort collect at least 20–50 forward ticks.
5. Write down the Cohort ID and Total Forward ticks.
6. Refresh once.
7. Confirm the same Cohort ID returns and Total Forward does NOT go back to 0.

Important
- v1.2 deliberately keeps only compact cumulative research state in localStorage. It does not persist the entire raw forward-record archive across refreshes.
- Export reports still include records collected in the current browser session plus cumulative candidate statistics preserved across refreshes.
